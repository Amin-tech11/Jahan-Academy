# Isolated main release

Only reviewed `main` is deployed. `develop` remains the local integration preview on port 5000. No shared Caddy configuration or unrelated site is changed. Existing project `jahan-academy-test`, PostgreSQL 17 and `db_data` are preserved.

CI builds both images, checks browser/API/integration/security regressions, publishes immutable commit tags, then passes registry digests to `release.sh`. Deployment is gated by repository variable `JAHAN_MAIN_DEPLOY_ENABLED=true` and the `production` environment. Configure `SSH_HOST`, `SSH_USER`, `SSH_PRIVATE_KEY`, `SSH_KNOWN_HOSTS`, optional `SSH_PORT`; never disable SSH host verification. Registry credentials are used in a temporary Docker config and removed after pulling. Missing deployment credentials keep automatic deployment disabled; they do not make CD successful.

The script verifies OCI commit labels, available RAM/disk, backs up the database, snapshots runtime files, runs migrations, checks all container health probes and public HTTPS routes, and records the commit. On failure it restores application images/configuration. Database rollback is deliberately manual: restore only a verified backup after assessing newer writes. New schema migrations must be additive for application rollback. Port 5080 remains an HTTPS redirect for untrusted callers.

Frontend receives only its BFF origin/URL and proxy credential. The credential is stripped at the API middleware and never printed. External forwarded-IP headers are ignored unless the isolated reverse proxy supplied the matching secret. The shared TLS proxy gateway is the only trusted forwarded-protocol/IP source. Verify this gateway when networking changes.

SMTP is explicitly disabled until an actual service is available. Then set `JAHAN_EMAIL_DELIVERY_ENABLED=true`, a verified `JAHAN_EMAIL_FROM`, SMTP host, port and exactly one of STARTTLS/implicit TLS. Test verification/reset with a controlled account. Recovery pages exist; disabled delivery returns a consistent 503 without account enumeration.

Daily maintenance executes retention separately from optional Celery integrations. `python -m app.modules.operational.maintenance` is a count-only dry run; `--apply` anonymizes eligible records in bounded batches. Review policy and dry run before initial production execution. Encrypted PostgreSQL backups (`jahan-*.dump.age` and ciphertext SHA-256 manifests) retain 14 days. Only nonempty encrypted files with completed manifests count as current backups in monitoring. Legacy plaintext dumps do not satisfy backup health and are not automatically deleted or converted. Inventory and re-encrypt existing copies separately with owner approval before retiring them. Offsite protection still requires a genuinely separate destination; until configured logs explicitly show `not_configured`.

Before enabling the revised backup job or releasing it, install `age` and configure a root-owned mode-0600 `/opt/jahan-academy-test/backup-encryption.env` containing `AGE_RECIPIENT=age1...` (a real recovery recipient generated on a separate trusted recovery host). Keep the private identity outside this server and its backups. No private key is generated or stored by the backup script. Existing `offsite-backup.env` recipient settings remain supported; `backup-encryption.env` takes precedence when both exist. A missing/invalid recipient or unavailable encryption tool fails before dumping data. `pg_dump` streams directly to `age`; neither temporary nor final plaintext dumps are written. Dump/encryption failures remove partial ciphertext and do not produce a successful backup. This code change does not install/configure anything on the production server.

For offsite copies, configure root-owned mode-0600 `/opt/jahan-academy-test/offsite-backup.env` with `OFFSITE_SSH_TARGET=user@separate-host:/absolute/path`, a restricted upload SSH key and verified host key. Both the already encrypted archive and its checksum are sent; a copy failure preserves the encrypted local backup and records failure. Verify recovery separately: on the recovery host, check `sha256sum -c <archive>.sha256`, then stream `age --decrypt --identity <offline-identity> <archive>` into `pg_restore --exit-on-error --dbname <isolated-restore-database>`. Do not count `pg_restore --list` alone as a restore drill. The operations tests exercise real age encryption/decryption, wrong keys, failed dumping/encryption/copying, and can restore a synthetic database when `BACKUP_TEST_SOURCE_DSN` and `BACKUP_TEST_RESTORE_DSN` point to disposable databases named `security_test` and `security_restore_test`.

Status/error logging uses `/opt/jahan-academy-test/operations.jsonl` and `maintenance.log`, rotated daily. It checks HTTPS, API readiness, service health, disk space and backup/retention freshness every five minutes. No external alert is sent. Monitor reports unavailable services/non-fresh jobs with a nonzero exit code. Do not store credentials, tokens, form contents or raw IPs in these logs.

MFA is mandatory for every staff role (`super_admin`, `support`, `consultant`, `content_editor`), including email logins and existing sessions. Password-only staff login or refresh returns `mfaEnrollmentRequired=true`; only MFA status/setup/confirmation, refresh and logout remain available until enrollment. The panel displays the setup gate instead of loading private data. Enrollment requires the account password and a valid TOTP code, returns ten one-use recovery codes, and revokes all existing sessions; staff must then sign in again with TOTP or a recovery code. Staff cannot disable MFA. Regular users retain optional MFA. Keep the stable `JAHAN_MFA_ENCRYPTION_KEY` in a separate encrypted secret backup; do not rotate it casually or expose it to the frontend. The release preparer generates this key only when absent. Verify that the key is present and backed up before releasing the policy. Recovery without authenticator/recovery codes requires a verified operator process; SMTP alone does not remove MFA.

Media publication writes the exact in-memory bytes that passed validation and malware scanning to the final storage key. It never re-copies the mutable quarantine object; an upload URL reused during scanning cannot replace the published content. No schema migration is required for these security changes.

Sessions expire after 30 minutes without a successful authenticated request and after 12 hours from the original login, whichever comes first. All staff roles use stricter defaults of 15 minutes and 8 hours. Configure `JAHAN_SESSION_IDLE_MINUTES`, `JAHAN_SESSION_ABSOLUTE_HOURS`, `JAHAN_STAFF_SESSION_IDLE_MINUTES`, and `JAHAN_STAFF_SESSION_ABSOLUTE_HOURS`; staff limits cannot be weaker than regular limits. Background authenticated polling counts as activity, but cannot extend the absolute lifetime. Every access and refresh checks server-side timestamps; refresh preserves the original family's deadline and cookie/access-token expiries are capped to it. Existing sessions are checked against their original family row, so rotating a legacy 30-day token cannot restart its lifetime. A missing original row fails closed. Successful authenticated requests persist activity under the same account/session lock order as rotation. No session schema migration or separate remember-me mode is introduced.

Backup execution requires GNU coreutils `timeout`: the entire job has a 1800-second deadline (plus a 5-second forced-stop grace), and each offsite transfer has a 300-second deadline. Operator environment overrides are `BACKUP_TIMEOUT_SECONDS` and `BACKUP_TRANSFER_TIMEOUT_SECONDS`. Retention runs after a complete encrypted local backup and before offsite copying, so SSH failure cannot prevent pruning. Deadline failures return nonzero; freshness monitoring remains required.
