# Full-site verification — 2026-10-07

Branch: `develop`. Integrated preview: `http://localhost:5000`.

## Scope and results

- Frontend: 171 passing Node tests, including API errors, validation, retry idempotency, receipts, LAN request keys, administration, bilingual content, navigation, motion, and regression coverage.
- Backend: 116 passing unit/architecture/contract tests; 18 passing integration scenarios against isolated PostgreSQL 18 and Redis 8. These cover authentication, permissions, consultations, lead management/workflow, catalog/content/media, reporting, and integrations.
- Ruff formatting/lint and mypy (171 source files) passed. Frontend TypeScript and production webpack build passed.
- Database migrations applied to head; latest migration downgraded and upgraded successfully in the disposable database. Existing application data was not migrated or removed.
- HTTP regression: 116 reachable public pages in Persian and English returned 200, with titles and successfully fetched JavaScript assets. Includes every one of the 30 university detail pages and 10 country pages in both languages. Admin/private routes and third-party URLs are excluded.
- Browser end-to-end: 12 real synthetic submissions through the UI. English: home, services, journal, destinations overview, Germany detail, about, universities, standalone consultation, assessment, contact. Persian over `http://192.168.8.61:5000`: services and assessment. Every submission displayed a reference matching a persisted lead, two consent records and exactly one accepted event.
- Contact form rejected an empty submission, focused the first invalid field, and accepted corrected input. Integration tests also verify invalid mobiles, deduplication, idempotent retries, reference collisions, and authorization.
- Mobile smoke checks: ten main routes in both languages at 390×844 (375px content viewport including scrollbar) had no horizontal document overflow. Six English panels also checked at desktop width. This is not an exhaustive visual/accessibility audit.

## Defects and performance improvements

1. Home news ticker hard-coded `/articles/` for news, causing two bilingual 404 links. It now uses the existing typed journal URL builder. A component regression test checks news, articles and guides in both duplicated ticker groups and both languages.
2. Server API origins ending in `/api/v1/` duplicated the version prefix. Normalization now removes trailing slashes before testing the prefix; the API URL test covers repeated trailing slashes.
3. Country detail client code imported the complete country, FAQ and university catalogs. The server now selects the current country's universities and FAQs and sends only lightweight related-country links. Content and interactions are preserved.
4. Selected-university image `sizes` now reflects the actual capped 1160px grid and its mobile breakpoints, avoiding oversized desktop downloads.
5. A separate `.next-audit` production build prevents benchmark builds from overwriting the active development server. `pnpm test:public` provides a repeatable read-only route/asset crawl and optional JavaScript payload budget. The GitHub-hosted CI lint job runs the crawl after its production build and uploads the report/log with the [official artifact action](https://github.com/actions/upload-artifact).

Measured on the same machine with Next 16.3.6, webpack, production server at port 5100:

| Metric | Before | After |
| --- | ---: | ---: |
| Country page initial JavaScript, gzip estimate | 235,727 B | 209,296 B |
| Germany English HTML + initial JavaScript, gzip estimate | 248,658 B | 223,413 B |
| McGill image WebP, desktop DPR 1 example (640→384px) | 64,702 B | 24,714 B |

Country JavaScript decreased 11.2%; combined initial HTML/JavaScript decreased 10.2%. The representative card image decreased 61.8%. Gzip figures are locally calculated payload estimates, not browser transfer timings. No claim of a Lighthouse score, Core Web Vitals, universal speedup, or theoretical maximum performance is made. Local request latency includes machine load and is not used as proof of speedup.

## Reproduction

From `frontend` in PowerShell, with port 5100 free:

```powershell
$env:JAHAN_PERFORMANCE_BUILD='1'
pnpm build --webpack
pnpm start --port 5100
```

In a second terminal in `frontend`:

```powershell
$env:AUDIT_OUTPUT='F:/Jahan Academy/site-audit.json'
$env:AUDIT_MAX_DESTINATION_JS_GZIP_BYTES='220000'
pnpm test:public
```

Use the same bundler when comparing payload budgets. CI uses its existing default production bundler and runs the route/asset regression without a webpack-specific budget. `next start` warns when standalone output is configured; it served this local audit correctly. Deployment should use the existing standalone container entry point.

Local raw evidence is stored outside Git under `F:/Jahan Academy/qa-{baseline-full,final,browser-results,responsive,persistence}.json`, frontend/build logs, and `design-previews/qa-lan-assessment.png`.

## Limits and test data

- Test leads are explicitly named `QA Audit … Do not contact`, use reserved example phone numbers and example.com email addresses, and remain in the local database for review. No real user's record was altered.
- Admin UI at port 3500 was not running; the integrated `/admin` displayed its login screen without an active session. Live admin-screen verification is therefore not claimed. Storage was independently checked read-only; admin list/detail/permission behavior passed the isolated integration suite.
- LAN checks used the network address from the host browser, not a second physical device. Safari/Firefox and real mobile hardware were not tested.
- Automated UI evidence was collected through the available browser tool; it is distinct from the repeatable HTTP regression added to CI. Passing these checks does not imply every conceivable user flow is covered.
- Two backend deprecation warnings concern TestClient/httpx and an anyio alias; they do not fail tests. No schema or permission redesign was needed for these fixes.
