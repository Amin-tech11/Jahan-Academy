## طراحی و مراحل تأیید

- طراحی API و مجوز: فیلتر و facet محدود و parameterized، حفظ scope کارشناس؛ MFA فقط برای حساب احرازشده با CSRF و اثبات رمز؛ حفاظت IP مبتنی بر اعتبار پراکسی خصوصی.
- دیتابیس: مهاجرت افزایشی `025_mfa`؛ بدون تغییر داده‌های تولید. برگشت و اجرای دوباره مهاجرت در دیتابیس اختصاصی تست موفق بود.
- تست محلی: ۱۳۷ تست واحد/معماری/قرارداد بک‌اند، ۲۳ تست یکپارچگی PostgreSQL/Redis، ۱۸۸ تست فرانت‌اند، ۲۱ سناریوی مرورگر تولید و ۳ بررسی مجدد صفحات develop روی پورت ۵۰۰۰ موفق شدند. هفت سناریوی اضافی حفاظت از پرونده دارای فعالیت جدید نیز روی PostgreSQL مستقل موفق شدند؛ تعداد تست یکپارچگی در CI اکنون ۳۰ است.
- عملیات: سه تست ابزارهای لینوکسی، تست Nginx واقعی با اتصال معتبر و جعل هدر، اعتبارسنجی Compose با متغیرهای ساختگی، Bash syntax و actionlint موفق بودند. dump در دیتابیس جداگانه بازیابی و schema/roles بررسی شد.
- ممیزی HTTP: ۱۱۰ مسیر بدون خطای صفحه، فایل یا سقف حجم. بیشترین JS محاسبه‌شده ۲۱۲٬۳۴۳ بایت gzip بود. این عدد و زمان محلی معادل LCP/INP کاربران واقعی یا نتیجه تست بار نیستند.
- امنیت و کیفیت: Ruff، mypy، TypeScript، Bandit و ممیزی وابستگی تولید Python موفق بودند. تأیید نهایی CI و اسکن ایمیج‌ها در PR ثبت می‌شود؛ اجرای انجام‌نشده موفق محسوب نمی‌شود.
- مراحل غیرقابل اعمال: بازطراحی موبایل، مدیریت محتوا، مجله و upload عمداً اجرا نشده‌اند؛ تست تحویل SMTP و بازیابی نسخه offsite بدون سرویس/مقصد واقعی قابل انجام نیست.

## محدودیت‌ها و پیش‌نیاز انتشار

1. SMTP موجود نیست. بازیابی ایمیلی تا پیکربندی و آزمون سرویس واقعی غیرفعال می‌ماند؛ کنترل احراز هویت برای رفع این محدودیت دور زده نشده است.
2. مقصد مستقل پشتیبان معرفی نشده است. وضعیت `not_configured` ثبت می‌شود؛ هنگام تنظیم مقصد، کپی ناموفق یا قدیمی به‌عنوان خرابی گزارش می‌شود.
3. کلید پایدار MFA باید در پشتیبان محرمانه جداگانه نگهداری شود. از دست دادن آن، دسترسی به کلیدهای TOTP را مختل می‌کند؛ ایمیل به‌تنهایی MFA را حذف نمی‌کند.
4. برای CD خودکار باید متغیر `JAHAN_MAIN_DEPLOY_ENABLED` و تنظیمات خصوصی SSH در GitHub آماده باشند. هیچ تنظیم محرمانه یا سرویس تولید در این مرحله تغییر نکرده است.
5. اجرای اولیه نگهداری باید همراه بازبینی dry-run و backup باشد. بی‌نام‌سازی داده فعال برگشت‌پذیر نیست؛ rollback خودکار کد، دیتابیس را به عقب برنمی‌گرداند. داده‌ای که قبلاً به سامانه خارجی منتقل شده، نیازمند فرایند حذف همان ارائه‌دهنده است.
6. پیش‌نمایش فرانت‌اند روی ۵۰۰۰ از develop است؛ API قبلی محلی روی ۱۸۰۸۰ از checkout ادمین اجرا می‌شود و در این کار دستکاری نشده است. اصلاحات API با دیتابیس و Redis جداگانه تست شدند. انتشار اصلی باید کل دو ایمیج main را با هم به‌روز کند.

فایل‌های اصلی تغییر در `backend/app/core`، `backend/app/modules/identity`، `backend/app/modules/consultations`، `backend/app/modules/operational`، `database/sql/025_*`، پوسته‌ها/متادیتا و اجزای مشترک `frontend`، `frontend/browser-tests`، `deploy/production` و `.github/workflows/ci-cd.yml` قرار دارند. سرور سایت دیگر و تنظیم Caddy مشترک دست‌نخورده‌اند.
